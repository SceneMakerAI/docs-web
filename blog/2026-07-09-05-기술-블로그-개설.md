개발 과정에서 달마다 글을 블로그에 작성하기로 했다.

공식 문서도 있고, 커뮤니티가 활달하며, 아래와 같은 아키텍처까지 볼 수 있다는 것에 놀랐다.

### Notion to Docusaurus 동기화

작성 글 퍼블릭 배포할 예정인 우리는, 아래 과정을 거쳐 동기화했다.

##### 1. Notion 글 작성

- 협업 시 Notion 을 오랫동안 써왔기에, 일단 생각나는 대로 적기 시작했다

![image](/img/blog/05-기술-블로그-개설/img-02.png)

##### 2. docusaurus config 설정 

- 공식 문서 참고 추천한다 ([https://docusaurus.io/ko/docs/cli](https://docusaurus.io/ko/docs/cli) )
- docusaurus.config.ts 파일. 우리의 url 과, github 페이지를 연결하였다.
  ```typescript
  const config: Config = {
    title: 'SceneMakerAI',
    tagline: '오픈소스 AI로 방송 콘텐츠를 재가공하다 — SceneMakerAI 기술 블로그 · 문서',

    ... 
              sameAs: ['https://github.com/SceneMakerAI'],
              parentOrganization: { '@type': 'Organization', name: '솔박스(Solbox Inc.)' },
            },
            {
              '@type': 'WebSite',
              name: 'SceneMakerAI Docs',
              url: 'https://doc.scenemaker.solbox.com',
            },
          ],
        }),
      },
  ```

##### 3. Notion-to-md 복사

- Notion Token 발급 / 데이터베이스 별 ID 확인 필요하다
  ```bash
  NOTION_TOKEN= 
  ...
  NOTION_RELEASE=
  NOTION_INSTALL=
  ```

- notion_to_md.py 로, Notion 내용이 서버에 나타난다

![image](/img/blog/05-기술-블로그-개설/img-03.png)

##### 4. workflow 동기화

- build 와 deploy 과정으로 분할 
  - build: main branch 코드 읽기, md 파일 → 정적 파일 (HTML/CSS/JS) 로 변환 

  - deploy: [doc.scenemaker.solbox.com](http://doc.scenemaker.solbox.com/) 반영 
    ```yaml
    name: Deploy to GitHub Pages

    jobs:
      build:
         ...

          - name: Install dependencies
            run: npm ci

          - name: Build (production, all locales)
            run: npm run build

      deploy:
        name: Deploy
        needs: build
        runs-on: ubuntu-latest
        environment:
          name: github-pages
          url: ${{ steps.deployment.outputs.page_url }}

    ```
