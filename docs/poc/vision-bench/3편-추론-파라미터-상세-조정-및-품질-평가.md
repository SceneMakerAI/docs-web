## 1. 들어가며

2편(OFAT 스윕)은 정답지 없이 판정 가능한 **순응** 기준으로 `temperature 0.7 · 페널티 off · dedup ON` 조합을 확정했습니다. 본 편은 그 다음 질문 **출력 내용이 얼마나 정확한가(품질)** 을 다룹니다.

정답 라벨이 없는 데이터이므로 상위 모델을 기준으로 삼아 다음과 같이 검증을 진행합니다.

1. 최강 조건의 Gemini 정답지(reference)를 만든다.
2. 같은 과제를 수행한 Qwen 출력을 LLM-judge로 채점 한다.
3. 2편이 남긴 페널티 크기의 품질 영향과 Qwen 품질의 한계·개선 방향을 정량화 한다.
   - fps·thinking 레버와 세부 조정은 후속 측정으로 진행

> 💡 **주의** : 본 편의 점수는 절대 정답이 아니라 **"최강 기준(Gemini) 대비 일치도"** 입니다. 같은 잣대로 채점한 상용 모델(gemini-3.5-flash)의 점수를 함께 제시해 Qwen 점수의 해석 기준점으로 삼습니다.

## 2. 평가 설계

세 모델을 4가지 역할(**평가 대상** · **조군** · **정답지** · **채점관)** 로 나눈다. 평가 대상과 대조군 정답지 모두 **같은 프롬프트·같은 6필드 strict 스키마** 로 같은 70 클립을 다루므로, **출력 텍스트끼리의 의미 비교가 곧 품질 채점** 이 된다.

검증은 2편과 같이 두 단입니다.

1. **형식** : 스키마·pydantic 이 기계적으로 강제
2. **품질** : 본 편의 LLM-judge 채점이 담당

### 2.1. 모델 구성 — 4역할(3개 모델)

| **역할** | **모델** | **영상 입력 조건** | **선정 이유** |
| --- | --- | --- | --- |
| 평가 대상 | Qwen3-Omni-30B-A3B  | fps 0.5 = 3프레임 + 오디오 | 검증 대상 모델 |
| 대조군1 | gemini-3.5-flash | fps 0.5 = 3프레임 + 오디오 | 동일 조건의 성능/비용 밸런스 대조군 |
| 대조군2 | gemini-3.1-pro-preview | fps 0.5 = 3프레임 + 오디오 | 동일 조건의 상위 모델 대조군 |
| 정답지 (reference) | gemini-3.1-pro-preview | **fps 24 = 144프레임 + 고해상도**  • 오디오 | 최고 모델 + 최대 정보 = 최강 기준 |
| 채점관 (judge) | gemini-3.1-pro-preview | 영상 없음 (텍스트 비교만) | 객관적 텍스트 의미 비교 |

#### **모델 스펙 비교**

| **항목** | **Qwen3-Omni-30B-A3B** | **gemini-3.5-flash** | **gemini-3.1-pro-preview** |
| --- | --- | --- | --- |
| 제공 형태 | 오픈소스 자가 서빙 | 상용 API (GA 안정판) | 상용 API (Preview) |
| 구조·파라미터 | Thinker–Talker MoE, 총 30B / 활성 3B | 비공개 (프런티어급) | 비공개 (최상위 추론) |
| 입력 모달리티 | 텍스트·이미지·오디오·비디오 | 텍스트·이미지·비디오·오디오·PDF | 좌동 |
| 컨텍스트 | 32,768 (실서빙 16,384) | 1,048,576 | 1,048,576 |
| 사고(thinking) | on/off 선택 — 기본 off 운용 | 동적 사고 내장 | thinking_level=high 기본 |
| 라이선스·비용 | Apache 2.0 / GPU 인스턴스 시간 | 종량 API | 종량 API |

#### **정답지·채점관을 gemini-3.1-pro 로 둔 근거**

- **공식 포지셔닝** : Google 이 "가장 발전된 추론(reasoning) 모델"로 공표한 현행 pro 라인 최신 버전입니다 (2026-02 출시, 구 gemini-3-pro 는 셋다운되어 이 ID 로 대체). [Google 공식 발표](https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-3-1-pro/)
- **추론 벤치마크 우위** : 공개 벤치마크 8종 중 flash(3.5)가 6종을 이기지만 전부 속도·에이전트·실무 영역이고, **순수 추론 최고난도 2종(ARC-AGI v2 77.1% · Humanity's Last Exam)은 3.1-pro 가 우위** 입니다. [llm-stats 비교](https://llm-stats.com/models/compare/gemini-3.1-pro-preview-vs-gemini-3.5-flash)
- **역할 적합성** : 정답지는 "영상을 가장 정확히 읽는 눈", 채점은 "두 텍스트의 의미 대응을 따지는 신중한 판정"으로, 둘 다 속도가 아니라 추론 품질이 좌우하는 작업입니다. 실무·속도형(flash)이 아니라 추론형(pro)을 배정한 이유입니다.
- **정답지의 정보 우대** : 모델 선정과 별개로, 정답지에는 fps 24(144프레임)·고해상도로 최대 정보를 줘 **"최고 모델 + 최대 정보 = 최강 기준"** 을 만들었습니다. 같은 모델이라도 입력 정보가 다르면 출력 정밀도가 달라짐은 §3.1 의 실측 대조로 확인했습니다.

### 2.2. 채점 방식 — LLM-judge 단일화

**"표현이 달라도 문맥·의미가 일치하면 정답"** 문장 생성 출력이라 문자열 정확 일치가 원천 불가능하고, 채점 기준의 수정·재적용 비용도 프롬프트 수정이 가장 쌉니다.

채점관은 클립마다 정답지와 후보 출력을 받아 **필드별로** 아래 3가지를 산출합니다.

| **산출** | **의미** |
| --- | --- |
| `score` (0\~5 정수) | 5=의미 완전 일치 \~ 0=무관·전부 환각. **환각은 누락보다 크게 감점** 하도록 명시 |
| `missed` | 정답지에 있는데 후보에 의미상 대응이 없는 항목 (누락 = recall 손실) |
| `hallucinated` | 후보에 있는데 정답지에 의미상 대응이 없는 항목 (환각 = precision 손실) |

> 채점관은 영상을 직접 보지 않으므로, hallucinated 는 엄밀히는 "환각"이 아니라 **"정답지에 없음"** 입니다. 정답지를 최강 조건(fps 24·고해상도)으로 만들어 이 간극을 줄였으며, 잔여 한계는 §5 에서 검증합니다.

### 2.3. 최종점수

**최종점수 = 클립별 6필드 score 평균 → 전 70클립 평균 (0\~5).** 스키마 검증에 실패(fail)한 클립은 0점으로 분모에 포함합니다 — 실패가 잦은 설정은 점수가 자동으로 깎입니다. 가중치·게이트 같은 합성 수식은 두지 않았습니다. 환각-누락의 경중은 채점 루브릭이 점수에 이미 반영하고, missed/hallucinated 항목 원문이 전부 저장되므로 다른 기준(예: precision 가중 F-점수)이 필요해지면 **재채점 없이** 사후 계산할 수 있습니다.

## 3. 테스트

### 3.1. 정답지 구축 — flash 에서 pro 로 격상

처음에는 GA 안정판 gemini-3.5-flash(fps 1)로 정답지를 만들었습니다. 그러나 **"기준 모델도 틀릴 수 있다"** 는 문제가 남아, 정답지를 **최고 모델 + 최대 정보** (gemini-3.1-pro · fps 24 · 고해상도)로 격상하고, flash 출력은 평가 대상(대조군 후보)으로 강등했습니다. 두 정답지 후보의 실측 대조:

| **정답지 후보** | **ok/fail** | **시각 항목 총수 (objects/ocr/actions)** | **청각 존재율 (bgm/sfx)** |
| --- | --- | --- | --- |
| flash · fps 1 | 70/0 | 393 / 219 / 235 | 72.9% / 61.4% |
| **pro · fps 24 (채택)** | 70/0 | **465 / 309 / 268** (ocr +41%) | 61.4% / 50.0% |

> pro 정답지는 시각(특히 화면 텍스트·점수판 세부)에서 압도적이지만 **청각에는 더 보수적** 입니다. 이 비대칭이 채점에 만드는 왜곡은 §5 에서 다룹니다.

### 3.2. 후보 설정 — 5종

| **후보** | **핵심 파라미터** | **의도** |
| --- | --- | --- |
| base | temp 0.7 · 페널티 off (2편 확정 조합) | 출발점 |
| freq 0.3 | base + frequency_penalty 0.3 | 페널티 크기 1D 스윕 |
| freq 0.5 | base + frequency_penalty 0.5 | 페널티 크기 1D 스윕 |
| 구03 재현 | temp 0.0 (greedy) + freq 1.1 | 1편 당시 운용값 — "실패 0" 설정의 품질 대가 측정 |
| flash | gemini-3.5-flash · fps 1 | 대조군 (상용 모델 기준점) |

공통 고정: 동일 70클립(7장르 × 10) · 동일 프롬프트·스키마 · max_tokens 512 · 오디오 on. fps·thinking 레버는 후속 측정으로 분리합니다.

### 3.3. 실행 파이프라인

실험 디렉토리 `experiments/03_param_tuning_quality_eval/` 의 3단 구성 — `run.py` (Qwen 측정) → `run_gemini.py` (정답지 생성) → `judge.py` (채점·집계, 6-병렬). 산출물은 `results/` (후보 출력) · `gold/` (정답지 캐시) · `scores/` (채점)로 분리됩니다.

```bash
# 정답지 1회 생성 (캐시 고정)
python run_gemini.py ../../data/sample70 --model gemini-3.1-pro-preview --fps 24 --media-resolution high -o gold/gemini31pro.json
# 후보 측정 (설정별)
python run.py ../../data/sample70 -o results/qwen_base.json
# 채점 (정답지 vs 후보)
python judge.py gold/gemini31pro.json results/qwen_base.json -o scores/qwen_base.json
```

## 4. 결과

### 4.1. 순응 재확인 — 페널티의 청각 대가

2편의 발견이 같은 표본에서 재현됐습니다. 페널티는 실패를 없애지만 **청각 정보를 비우는 방식** 으로 없앱니다.

| **설정** | **ok/fail** | **repeat** | **bgm 존재율** | **sfx 존재율** |
| --- | --- | --- | --- | --- |
| base (0.7 · 페널티 off) | 69/1 | 18.6% | **50.7%** | **44.9%** |
| freq 0.3 | 70/0 | 8.6% | 28.6% | 32.9% |
| freq 0.5 | 70/0 | 2.9% | 22.9% | 22.9% |
| 구03 재현 (greedy + freq 1.1) | **70/0** | 5.7% | 8.6% | 12.9% |

> 구03 재현의 "실패 0"은 사실입니다. 다만 bgm 이 70클립 중 6건만 남습니다 — 결함이 없는 게 아니라 **출력을 덜 해서 결함날 기회가 없는** 구조입니다. base 의 repeat 18.6% 는 dedup 후처리가 무손실 제거하므로 비용이 아닙니다.

### 4.2. 1차 채점 결과 (N=1)

| **후보** | **최종점수 (0\~5)** | **missed (누락)** | **hallucinated (환각)** |
| --- | --- | --- | --- |
| **gemini-3.5-flash (대조군)** | **3.20** | 533 | 354 |
| qwen freq 0.3 | 2.33 | 863 | 453 |
| qwen 구03 재현 | 2.29 | 897 | **307** |
| qwen base | 2.22 | **799** | 655 |
| qwen freq 0.5 | 2.20 | 906 | 442 |

#### 1. 잣대 자체가 깐깐하다 — Qwen ≈ flash 의 70%

프런티어급 flash 도 **3.20/5** 입니다. 최강 정답지(fps 24) 기준이라 만점이 구조적으로 어렵습니다. Qwen 2.2\~2.3 은 절대값이 아니라 **"flash 의 약 70% 수준"** 으로 읽는 것이 맞습니다.

#### 2. 장르 패턴이 fps 가설을 지지한다

Qwen 은 움직임이 빠른 장르에서 무너지고(esports 1.82 · drama 1.88 · baseball 1.98) 정적인 사극에서는 3.0 으로 flash(3.5)에 근접합니다. flash 는 전 장르 3.0\~3.5 로 균일합니다. **3프레임(fps 0.5)으로는 동적 장면을 따라가지 못한다** 는 신호 — 후속 fps 측정의 관전 포인트입니다.

#### 3. 샘플링은 품질 레버가 아니다

환각은 페널티에 용량-반응으로 감소하고(base 655 → 구03 307) 누락은 역방향(799 → 906)으로 늘어, trade-off 가 숫자로 드러났습니다. 그러나 **설정 간 최종점수 격차는 0.13** 에 불과합니다. 어떤 샘플링 조합도 품질 천장(\~2.3)을 깨지 못합니다 — 품질의 본체는 모델 체급과 입력 정보량이고, 샘플링 튜닝의 역할은 2편(순응)에서 이미 끝났습니다.

## 5. 채점 검증과 한계

채점 결과를 그대로 믿지 않고, 표본 클립에서 정답지·후보 출력·채점 내용을 3중 대조(눈검증)했습니다.

#### 정당한 감점 — Qwen 의 실제 약점

- **actions 가 내용이 아니라 카메라 묘사** — 정답 "서류를 넘기다 · 수어를 하다" vs Qwen "보여주다 · 분석하다 · 삽입되다" (score 0 정당)
- **bgm 에 소리가 아닌 분위기 형용사** — "신뢰감 있는", "공식적인" (환각 판정 정당)
- **시각 디테일 누락** — 수어 통역사, 키보드 등 (3프레임 한계)

#### 채점 편향 — 수정 가능한 3건

- **① dedup 미적용 채점** — 후보 출력의 exact-중복("KBS NEWS" ×2)이 환각으로 집계됨. 확정 파이프라인(dedup ON)대로 채점 전에 제거해야 함
- **② ocr 분할 단위 이중 처벌** — 같은 텍스트를 다르게 쪼갠 경우("2018년 울산지검" vs "2018년 울산지검 **인용** ") missed 와 hallucinated 양쪽에 동시 계상
- **③ 청각 빈-정답지 왜곡** — pro 정답지가 청각에 보수적(sfx 존재율 50%)이라, 후보가 개연성 있는 소리(esports 의 "게임 음악")를 적어도 0점, **아무것도 안 적으면 빈-빈 매칭으로 5점** . 침묵하는 설정이 유리해지는 구조적 편향

> 편향 ③은 페널티 설정(청각 출력이 적은 쪽)에 유리하게 작용합니다. **1차 순위(freq 0.3 > base, 격차 0.11)는 이 왜곡 범위 안이므로 편향 수정 재채점 전까지 잠정** 입니다.

#### 구조적 한계 — 동일 가족 채점

정답지·채점관·대조군2가 모두 같은 모델(대조군1도 같은 Gemini 계열)인 **동일 가족 채점 구조** 입니다. 같은 모델이 쓴 정답지와는 표현 습관이 닮아 의미 매칭에 유리할 수 있어, Gemini 계열 후보(대조군)의 점수가 구조적으로 후할 가능성이 있습니다. 채점 기준("표현이 달라도 의미 일치면 정답")이 이를 완충하며, 소표본을 다른 채점관(flash)으로 교차 채점해 순위 견고성을 확인할 수 있습니다.
