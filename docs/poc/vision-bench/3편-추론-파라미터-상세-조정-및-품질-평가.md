## 1. 들어가며

편2(추론 파라미터 튜닝 1단계)가 *정답지 없이 확정 가능한 것* 까지 좁혀 줬다. 본 편은 **Gemini 정답지로 출력 품질을 정량화** 하고, 편2 가 남긴 파라미터(페널티 *크기* ·fps)와 전반적 품질을 **목적함수에 대고 최적화** 한다. (스윕 수치·golden set·장르별 F1 등 *결과* 는 실험 수행 후 채운다.)

## 2. 평가 설계

출력은 두 단으로 검증한다.

1. **형식 검증** — 스키마·pydantic 으로 4필드 구조를 기계적으로 강제한다(편1·편2 의 strict `json_schema` , 자동 100%).
2. **품질 평가** — 기준 모델(Gemini)로 정답지를 만들어 필드별 자동 지표로 **일치도** 를 측정하고, 표본은 사람이 정성 점검한다.

정답 라벨이 없어 절대 정확도의 자동 채점은 불가하다 → 현재 가장 우수한 **Gemini 출력을 기준(reference)** 으로 삼아 Qwen 출력의 일치도를 정량화한다. 문자열 정확 일치 대신 **의미 기반 매칭** (임베딩 유사도)을 써 동의어(예: "앵커"≈"뉴스 앵커")를 동일 처리한다. 단, 점수는 절대 정답이 아니라 **"Gemini 대비 일치도"** 이며, **표본 10\~20클립은 사람이 직접 점검** 해 Gemini 라벨 신뢰도를 보정한다.

### 2.1. 품질 평가 지표 (Gemini 정답지 대비)

| **필드** | **지표** | **측정 방식** | **잡아내는 것** |
| --- | --- | --- | --- |
| `objects` | Precision / Recall / **F1** | 항목 임베딩 코사인 ≥ 임계값 매칭 후 집합 비교 | Precision=환각·오탐, Recall=누락 |
| `actions` | Precision / Recall / **F1** | 위와 동일 | 동작·장면전환 포착력 |
| `audio` | Precision / Recall / **F1** | 항목 임베딩 코사인 매칭 (objects·actions 와 동일) | 대사·효과음·배경음 포착력·환각 |
| `summary` | **BERTScore** (P/R/F1) | Gemini 요약과 의미 유사도 | 내용 일치·왜곡·환각 |
| 전 필드 | 코사인 유사도 (0\~1) | 문장 임베딩 코사인 | 전체 의미 일치도 점수 |

### 2.2. 정량 지표 (운영, 자동 집계)

| **지표** | **설명** |
| --- | --- |
| 처리 성공률 | ok / fail (HTTP 에러 비율) |
| 추론 평균 시간 | Qwen 추론 평균 (ms) |
| 토큰 평균 사용량 | prompt / completion avg per clip |

> ⚠️ 점수는 "정답"이 아니라 **기준 모델(Gemini)과의 일치도** 다. Gemini 자체 오류 가능성은 표본 사람 점검으로 보정한다.

## 3. 이후 작업 (예정)

편2 가 좁혀 준 탐색을 위 Gemini 목적함수에 대고 수행한다.

- **페널티 크기 1D 스윕** — freq(0\~0.7) 또는 rep(1.0\~1.2) 중 하나를 F1 목적함수로 최적화 (둘 다 켜지 않음)
- **fps 최적값** — 정확도-토큰 트레이드오프 (베이스라인 30fps vs 0.5fps 활용)
- **최종 파라미터 확정 (golden set)**
- **장르별 강·약점** — 7카테고리 F1
