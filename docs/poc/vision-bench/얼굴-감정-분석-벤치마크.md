### 1. 개요

#### 1.1 배경

- 드라마 장면에서 인물의 감정(기쁨·화남·슬픔 등)을 태깅해 검색·클립 추출에 쓰려고 함
- 영상 화면의 인물들의 얼굴 표정을 분석하기 위하여, OpenCV FER 의 성능을 실제 테스트 하기 위하여
- 모든 얼굴에서 감정을 잡아 내는 것이 아닌, 중요 상황에서만 감정을 찾아내는 것이 중요 함
- 조건: **오픈소스, 파인튜닝 없음, 단일 모델로 기본 표정 분류**


#### 1.2 PoC 목적

1. 라이선스 문제로 OpenCV_FER 를 사용하지만, 해당 모델의 실질적인 테스트를 위해 사용 함
2. 서비스에서 쓸 **정답 클래스 체계** 와 **확률 기준값**  결정
3. 추후 내부 프로세스에 그대로 붙일 수 있는 **라이브러리 구조**  확정


#### 1.3 결정사항

| 항목 | 결정 |
| --- | --- |
| 정답 클래스 | **기쁨 / 화남 / 슬픔 / 놀람 / 일반**  5개 (모델 클래스를 묶음) |
| 묶음 점수 | 묶인 클래스 softmax 확률의 **합** |
| 기준값 | **0.8 권고**  (감정 묶음 점수 0.8 미만이면 일반으로 보냄) |
| 모델 | **잠정 OpenCV FER**  — 빠르고, 가장 많이 엇갈린 경우에 육안상 맞는 쪽. 최종 확정은 정답 라벨 평가 후 |
| 구조 | `lib/model_emotion/`  하나만 워커로 옮기면 되게 분리 (검출기와 독립) |

#### 1.4 처리 흐름

```text
프레임(jpg, 1fps)
  → insightface buffalo_l : 얼굴 박스 + 5점 랜드마크 + 임베딩
  → 얼굴 필터 (검출 점수 ≥ 0.6, 한 변 ≥ 60px)          ← 워커와 동일
  → 감정 모델 2종 (같은 얼굴에 둘 다)
       OpenCV FER : 5점 정렬 112×112
       hsemotion  : 박스 크롭 224×224
  → softmax 확률 → 5개 정답으로 묶기 → 기준값 적용
  → 인물 군집 (워커와 동일)
```

### 2. 비교 설계

#### 2.1 모델

|  | **OpenCV FER**  (Progressive Teacher) | **hsemotion**  (EmotiEffLib) |
| --- | --- | --- |
| 파일 | `facial_expression_recognition_mobilefacenet_2022july.onnx`  (4.6MB) | `enet_b0_8_best_vgaf.onnx`  (16MB) |
| 백본 | MobileFaceNet | EfficientNet-B0 |
| 클래스 | 7개 | 8개 (경멸 포함) |
| 입력 | 5점 랜드마크로 정렬한 112×112, `(x/255−0.5)/0.5` | 박스 크롭 224×224, ImageNet 평균·표준편차 |
| 공개 정확도 | RAF-DB 88.27% | AffectNet 8클래스 61.32% |
| 실행 | onnxruntime-gpu (배치 1 고정) | onnxruntime-gpu |

> 두 모델 모두 공식 패키지 없이 onnxruntime으로 직접 돌린다. 내부 적으로 이미 onnxruntime-gpu를 쓰고 있어 **새 의존성이 없다.** emotiefflib 패키지는 CPU로 고정돼 있어 사용하지 않음.

**제외한 후보**

- LibreFace: 성능은 좋으나 USC 연구용 라이선스(상업 이용 불가)
- POSTER / POSTER++: 코드는 MIT, 공개 가중치는 라이선스 표기 없음

#### 2.2 정답 매핑

| 정답 | OpenCV | hsemotion | 묶은 이유 |
| --- | --- | --- | --- |
| **기쁨** | happy | happy |  |
| **화남** | angry, disgust | angry, disgust, contempt | 찌푸리고 일그러뜨리는 표정. 모델끼리 자주 섞임 |
| **슬픔** | sad | sad |  |
| **놀람** | surprise, fear | surprise, fear | 둘 다 눈을 크게 뜨고 입을 벌림. |
| **일반** | neutral | neutral | 위 4개를 제외한 그외의 것들 |

- **묶음 점수** 는 묶인 클래스 확률의 합이고, 다섯 묶음의 합은 1입니다.
- 묶음 점수가 가장 높은 정답을 고르고, 그게 감정인데 **기준값 미만이면 일반** 으로 보냅니다.
- 예를 들어 기준값 0.9에서 기쁨이면 나머지 네 묶음의 합은 0.1 이하입니다.

#### 2.3 변수

- 기준값: **0.5 / 0.6 / 0.7 / 0.8 / 0.9**
- 모델을 다시 돌리지 않고, 저장한 확률에 기준값만 바꿔 다시 계산합니다.

#### 2.4 측정 지표

정답 라벨이 없으므로 **두 모델끼리의 일치율** 을 정확도 대신 씁니다.

| 지표 | 계산 | 뜻 |
| --- | --- | --- |
| 전체 일치 | 같은 정답 / 전체 얼굴 | 둘 다 일반인 얼굴이 대부분이라 기준값을 올리면 저절로 오름 |
| 감정 기준 일치 | 같은 정답 / 한쪽이라도 감정을 붙인 얼굴 | "감정이 있는 얼굴인가"에 대한 합의 |
| **감정 일치** | 같은 감정 / 둘 다 감정을 붙인 얼굴 | "무슨 감정인가"에 대한 합의 |

분포 표에서는 일반을 둘로 나눕니다.

- **일반 (중립이 1등)** : 기준값과 무관하게 고정
- **보류 (감정이 1등인데 기준 미만)** : 기준값을 올릴수록 늘어남

### 3. 구현

#### 3.1 디렉토리 구조

```text
poc-face-emotion/
├── config.py                 경로 / 디바이스 / 모델 위치 (워커 config.py 와 같은 모양)
├── main.py                   영상 1편: 검출 + 감정 2종 → output/{v_id}_{stream_id}/
├── script/
│   ├── download_models.sh    감정 모델 ONNX 2종 받기
│   └── sweep.py              기준값 0.5~0.9 비교 → output/sweep/
└── lib/
    ├── model_emotion/        ← 워커로 옮길 라이브러리
    │   ├── frame.py            Emotion 데이터 / 라벨 / 정답 매핑 / 기준값
    │   ├── onnx_util.py        세션(GPU 확인) / 추론 / 5점 정렬 / 크롭
    │   ├── opencv_fer.py       OpenCV FER 백엔드
    │   ├── hsemotion.py        hsemotion 백엔드
    │   └── pipe_model.py       Models.load() + run() + to_group()
    ├── model_face/           ← 워커 코드 복사, 바뀐 줄에 # [emotion] 표시
    └── report/               ← PoC 전용 리포트·시트
```


#### 3.2 내부 모듈 연동 설계

- **감정 분석 코드는 얼굴 검출 코드와 분리함**
  - 감정 분석은 "프레임 이미지 + 얼굴 위치(박스) + 눈·코·입 위치(5점)"만 받아서 동작함

  - 지금은 insightface가 얼굴을 찾아 주지만, 나중에 다른 얼굴 검출 모델로 바꿔도 감정 분석 코드는 손대지 않아도 됨

- **얼굴을 찾는 단계에서 감정 분석을 같이 돌림**
  - 얼굴을 찾은 직후에 원본 프레임과 얼굴 위치가 함께 있으므로, 그 자리에서 바로 감정 분석을 함

- **내부 모듈에 붙이는 방법은 간단함**
  - `lib/model_emotion/`  폴더를 그대로 복사함

  - 기존 얼굴 검출 코드에서 `# [emotion]` 으로 표시해 둔 몇 줄만 옮김

- **실행 환경은 내부 모듈과 동일하게 맞춤**
  - Python 3.12.0과 패키지 버전을 내부 모듈과 같게 고정해, PoC 결과가 내부 모듈에서도 그대로 나오도록 함


#### 3.3 구현 검증

> ✅ 두 모델 모두 **공식 구현과 얼굴 87개에서 라벨 87/87 일치** (확률 차 ≤ 0.002)

검증 중 발견한 문제는 두 가지

| 문제 | 증상 | 조치 |
| --- | --- | --- |
| 얼굴 정렬 방식 | `cv2.estimateAffinePartial2D` (이상치 제거 방식)로 정렬하면 원본과 7개 라벨이 달라짐 | OpenCV Zoo 원본과 같은 **5점 최소제곱 정렬** 로 교체 → 87/87 |
| 배치 추론 지연 | 프레임마다 얼굴 수가 달라 배치 크기가 바뀌면 호출당 **60ms**  (모양이 같으면 1.2ms) | 얼굴을 **한 장씩**  추론 |

### 5. 결론

> **기준값 0.8 \~ 0.9 권고** (중요한 장면만 확실하게 잡으려면 0.9, 감정 장면을 더 많이 잡으려면 0.8)

- **0.8에서 처음으로 감정 일치가 90%를 넘음**
  - 합계 91.3% (1027 89.7%, 1055 93.0%)

- **0.9에서는 감정 일치가 98.5%로 가장 높고, 남는 감정 표정이 뚜렷함**
  - OpenCV FER 기준으로 기쁨 552개, 슬픔 152개, 놀람 176개가 남아 서비스에 쓰기에 충분함

  - 0.8 → 0.9로 올릴 때 빠지는 얼굴은 옅은 미소, 심각한 얼굴, 말하느라 입을 벌린 얼굴이 대부분이라 놓쳐도 손실이 적음

- **0.7 이하는 두 모델이 서로 다른 감정을 붙이는 얼굴이 15% 넘게 섞임**

**기준값으로 해결되지 않는 것**

- **화남(Angry)은 0.9에서 35개(0.4%)뿐이고 표정도 애매함**
  - 화남만 기준값을 따로 낮추거나 별도 판단이 필요함

- **"감정 기준 일치"**
  - 두 모델은 "무슨 감정인가"는 잘 맞히지만 "감정이 있는 얼굴인가"에서 갈림

  - 기준값을 올려도 양쪽이 다르게 판단한 정답이 줄어 듬.
