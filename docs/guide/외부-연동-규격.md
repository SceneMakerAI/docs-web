## 영상 그룹

영상 그룹은 영상(video)을 묶는 단위다. 드라마 한 시리즈, 야구 한 경기가 그룹 1건이고, 그 아래에 영상이 회차(`order_no` )로 달린다. 카테고리(`cate_id` )와 완료 콜백(`callback_url` )은 영상이 아니라 그룹의 속성이다.

예) 김부장 (1\~10편) 이 있다면 “김부장” 이 영상 그룹이고 “김부장-1편”, ”김부장-2편” 은 영상으로 들어간다.

| `POST` | `http://<host>:<port>/api/v1/video_group` | 그룹 등록. `v_g_id`  를 발급해 돌려준다 |
| --- | --- | --- |
| `PUT` | `http://<host>:<port>/api/v1/video_group` | 그룹 수정. 전체 교체 방식 |


### 영상 그룹 생성

#### Request

- 예제

```bash
POST http://{HOST}:{PORT}/api/v1/video_group
Content-Type: application/json

{
  "cate_id": 5100,
  "name": "2026 KBO 정규시즌",
  "callback_url": "http://sbs.co.kr/",
  "comment": "정규시즌"
}
```

- 설명

| 필드 | 필수 | 타입 | 크기 | 설명 |
| --- | --- | --- | --- | --- |
| cate_id | 필수 | int | - | 카테고리 ID |
| name | 필수 | str | 1\~100 | 그룹 이름 |
| callback_url | 선택 | str | 200 | 그룹 전체 공정이 끝났을 때 통보받을 URL |
| comment | 선택 | str | 200 | 비고 |

#### Response

```bash
{"code": 0, "result": "OK", "v_g_id": 12}
```


### 영상 그룹 수정

#### Request

- 예제

```bash
PUT http://{HOST}:{PORT}/api/v1/video_group
Content-Type: application/json

{
  "v_g_id": 12,
  "cate_id": 5100,
  "name": "2026 KBO KT vs NC",
  "callback_url": "http://sbs.co.kr/",
  "comment": "정규시즌"
}
```

- 설명

| 필드 | 필수 | 타입 | 크기 | 설명 |
| --- | --- | --- | --- | --- |
| v_g_id | 필수 | int | - | 수정할 그룹 ID |
| cate_id | 선택 | int | - | 카테고리 ID |
| name | 선택 | str | 1\~100 | 그룹 이름 |
| callback_url | 선택 | str | 200 | 그룹 전체 공정이 끝났을 때 통보받을 URL |
| comment | 선택 | str | 200 | 비고 |


#### Response

```bash
{"code": 0, "result": "OK", "v_g_id": 12}
```

## 영상 타이틀

영상(video)은 분석 단위다. 드라마 한 회차, 야구 한 경기가 영상 1건이고, 영상 그룹(`v_g_id` ) 아래에 회차(`order_no` )로 달린다. 이름·방송 연도·스트림 여부(`stream_yn` )는 영상의 속성이고, 카테고리와 콜백은 그룹의 것을 따른다. 실제 영상 파일은 STT 요청(`stt_svc` ) 때 이 `v_id` 에 붙는다.

예) "김부장" 그룹에 "김부장-1편"(`order_no` 1), "김부장-2편"(`order_no` 2) 이 영상으로 들어간다. 야구는 경기 1건이 그룹이고 영상도 1건이다.

| POST | http://<host>:<port>/api/v1/video | 영상 등록. v_id 를 발급해 돌려준다 |
| --- | --- | --- |
| PUT | http://<host>:<port>/api/v1/video | 영상 수정. 부분 교체 방식 |


### 영상 타이틀 생성

#### Request

- 예제

```bash
POST http://{HOST}:{PORT}/api/v1/video
Content-Type: application/json

{
  "v_g_id": 12,
  "name": "2026 KBO KT vs NC",
  "order_no": 1,
  "play_year": 2026,
  "stream_yn": "N",
  "comment": "8월 31일 경기"
}
```

- 설명

| 필드 | 필수 | 타입 | 크기 | 설명 |
| --- | --- | --- | --- | --- |
| v_g_id | 필수 | int | - | 소속 그룹 ID |
| name | 필수 | str | 1\~50 | 영상 이름 |
| order_no | 선택 | int | - | 그룹 안 회차. 없으면 마지막 회차 + 1 |
| play_year | 선택 | int | - | 방송 연도 |
| stream_yn | 선택 | str | 1 | 스트림(조각) 영상이면 Y, VOD 전체면 N. 기본 N |
| comment | 선택 | str | 200 | 비고 |

#### Response

```bash
{"code": 0, "result": "OK", "v_id": 1012}
```


### 영상 타이틀 수정

#### Request

- 예제

```bash
PUT http://{HOST}:{PORT}/api/v1/video
Content-Type: application/json

{
  "v_id": 1012,
  "v_g_id": 12,
  "name": "2026 KBO KT vs NC",
  "order_no": 1,
  "play_year": 2026,
  "stream_yn": "N",
  "comment": "8월 31일 경기"
}

```

- 설명

| 필드 | 필수 | 타입 | 크기 | 설명 |
| --- | --- | --- | --- | --- |
| v_id | 필수 | int | - | 수정할 영상 ID |
| v_g_id | 선택 | int | - | 소속 그룹 ID |
| name | 선택 | str | 1\~50 | 영상 이름 |
| order_no | 선택 | int | - | 그룹 안 회차 |
| play_year | 선택 | int | - | 방송 연도 |
| stream_yn | 선택 | str | 1 | 스트림(조각) 영상이면 Y, VOD 전체면 N |
| comment | 선택 | str | 200 | 비고 |


#### Response

```bash
{"code": 0, "result": "OK", "v_id": 1012}
```

## 영상 분석

영상 파일을 등록하고 분석 공정을 시작한다. 그룹 등록 → 영상 등록 → 영상 분석 순서의 마지막 단계다. 미리 등록한 영상(`v_id` )에 실제 파일(S3 객체 키)을 붙이면 download → 음성·프레임 추출 → 자막(STT) 공정이 이어서 돈다. 제목·카테고리·연도·콜백은 그룹과 영상에 이미 있으므로 여기서는 받지 않는다.

예) **드라마는 VOD** 다. "김부장-1편" 영상(`v_id` 1012) 에 파일 하나를 붙이면 끝이고, `stream_id` 는 주지 않는다.  
**프로야구는 스트림** 이다. 경기 영상(`v_id` 2001) 하나에 1회초, 1회말, 2회초 … 조각이 차례로 들어온다. 조각마다 이 API 를 한 번씩 호출하고 `stream_id` 로 구분한다(`1top` , `1bot` , `2top` …). 마지막 조각(9회말 또는 연장 끝)에만 `last_yn` 을 Y 로 준다.

| POST | **http://<host>:<port>/api/v1/video_file** | **영상 파일 등록 + 분석 시작** |
| --- | --- | --- |

### 영상 타이틀 생성

#### Request

- 예제 (드라마, VOD)

```bash
POST http://{HOST}:{PORT}/api/v1/video_file
Content-Type: application/json
{
  "v_id": 1012,
  "file_path": "vod/2/202.mp4",
  "last_yn": "Y",
  "forced_yn": "Y"
}

```

- 예제(프로야구, 스트림)

```bash
POST http://{HOST}:{PORT}/api/v1/video_file
Content-Type: application/json
{
  "v_id": 1012,
  "file_path": "vod/2/202_1top.mp4",
  "stream_id": "1top",
  "last_yn": "N",
  "forced_yn": "Y"
}
```


- 설명

| 필드 | 필수 | 타입 | 크기 | 설명 |
| --- | --- | --- | --- | --- |
| v_id | 필수 | int | - | 영상 ID. 영상 타이틀 생성에서 발급된 값 |
| file_path | 필수 | str | 5\~200 | S3 객체 키. s3://버킷/ 은 붙이지 않는다 |
| stream_id | 선택 | str | 20 | 스트림 영상(stream_yn Y)이면 필수. VOD 는 생략 |
| last_yn | 선택 | str | 1 | 마지막 조각이면 Y. VOD 는 Y. 기본 Y |
| forced_yn | 선택 | str | 1 | Y 면 이미 등록된 조각을 지우고 다시 처리. 기본 Y |

#### Response

```bash
{"v_id": 1012, "stream_id": "VOD", "code": 0, "result": "OK"}
```

## 영상 검색(분석 내용 추출)

분석이 끝난 영상에 질의를 던져 장면을 고르고 하이라이트로 편성한다. 편성 단위는 그룹(`v_g_id` )이다. 드라마는 시리즈 전체(여러 회차)에서, 야구는 경기 1건에서 고른다. `videos` 를 주면 그 그룹 안에서 그 영상(과 조각)만 대상이고, 없으면 그룹 전부다. 편성은 1\~3분 걸리므로 접수만 하고 바로 응답하며, 완료는 `callback_url` 통보 또는 상태 조회로 확인한다.

예) 드라마 "김부장" 그룹(`v_g_id` )에 "재회 장면" 질의를 던지면 1\~10편 전체에서 고른다. 야구 경기 그룹(`v_g_id` )에 `videos` 로 7회 이후 조각(`stream_id_1` , `stream_id_2` …)만 주면 그 이닝 안에서 고른다.

| POST | http://<host>:<port>/api/v1/compose | 편성 접수. comp_id 즉시 발급 |
| --- | --- | --- |
| GET | http://<host>:<port>/api/v1/status_compose?comp_id= | 편성 상태 조회. |


### 편성 접수

#### Request

- 예제 (드라마, 그룹 전체)

```bash
POST http://{HOST}:{PORT}/api/v1/compose
Content-Type: application/json

{
  "v_g_id": 12,
  "query": "주인공 둘이 재회하는 장면",
  "budget_sec": 180,
  "callback_url": "http://sbs.co.kr/"
}
```

- 예제 (프로야구, 조각 지정)

```bash
POST http://{HOST}:{PORT}/api/v1/compose
Content-Type: application/json

{
  "v_g_id": 30,
  "videos": [
    {"v_id": 2001, "stream_ids": ["7top", "7bot", "8top", "8bot", "9top", "9bot"]}
  ],
  "query": "역전 장면만",
  "budget_sec": 90,
  "callback_url": "http://sbs.co.kr/"
}
```

- 설명

| 필드 | 필수 | 타입 | 크기 | 설명 |
| --- | --- | --- | --- | --- |
| v_g_id | 필수 | int | - | 편성 대상 그룹 ID |
| videos | 선택 | list | 1\~ | 대상 영상 목록. 없으면 그룹의 영상 전부 |
| videos[].v_id | 필수 | int | - | 영상 ID. 그 그룹 소속이어야 한다 |
| videos[].stream_ids | 선택 | list[str] | 20 | 조각(stream_id) 목록. 없으면 그 영상의 파일 전부 |
| query | 필수 | str | 1\~200 | 찾고 싶은 장면을 문장으로. "홈런", "역전 장면" 등 |
| budget_sec | 선택 | int | - | 목표 분량(초). 없으면 절단하지 않는다 |
| callback_url | 선택 | str | 200 | 편성 완료 시 결과를 통보받을 URL |

#### Response

```bash
{"comp_id": 7, "code": 0, "result": "OK"}
```

접수 거절은 HTTP 상태로 종류를 알리고, 본문은 요청 키 + 사유(`reason` ) + `code` -1 / `result` "fail" 이다.

| 상황 | HTTP | 본문 |
| --- | --- | --- |
| 그룹 없음 | 404 | `{"v_g_id": 12, "reason": "영상 그룹이 없습니다.", "code": -1, "result": "fail"}` |
| 영상·조각 없음 | 404 / 422 | `{"v_g_id": 12, "v_ids": [1099], "reason": "그룹에 속하지 않은 영상이 있습니다.", "code": -1, "result": "fail"}` |
| 분석 미완료 | 422 | `{"v_g_id": 12, "files": [{"v_id": 1012, "stream_id": "VOD", "status_code": 2011}], "reason": "분석이 끝나지 않은 영상이 있습니다.", "code": -1, "result": "fail"}` |
| 편성 중 (처리량 초과) | 409 / 429 | `{"v_g_id": 12, "reason": "편성이 진행 중입니다. 잠시 후 다시 요청해 주세요.", "code": -1, "result": "fail"}` |
| LLM 서버 불가 | 503 | `{"v_g_id": 12, "reason": "LLM 서버를 사용할 수 없습니다. 잠시 후 다시 요청해 주세요.", "code": -1, "result": "fail"}` |
| 요청 형식 오류 | 422 | 표준 검증 오류 |


### 편성 상태 조회

접수 응답의 `comp_id` 로 진행 상태를 조회한다. `code` / `result` 는 조회 자체의 성공 여부이고, 편성 상태는 `status_code` / `status_name` 이 말한다.

#### Request

```bash
GET http://{HOST}:{PORT}/api/v1/status_compose?comp_id=7
```

#### Response

```bash
[진행 중]
{"comp_id": 7, "code": 0, "result": "OK", "status_code": 4020, "status_name": "장면 선곡 중"}

[완료]
{"comp_id": 7, "code": 0, "result": "OK", "status_code": 4000, "status_name": "하이라이트 처리 완료"}

[실패]
{"comp_id": 8, "code": 0, "result": "OK", "status_code": 4900, "status_name": "편성 실패"}

[대상 없음]
{"comp_id": 9, "code": -1, "result": "fail"}
```

| status_code | 뜻 |
| --- | --- |
| 4000 | 완료. 결과는 콜백으로 통보됨 |
| 4001 | 완료. 조건에 맞는 장면 없음 (clips 빈 목록) |
| 4010 \~ 4050 | 진행 중. 증거 색인 → 장면 선곡 → 클립 구성 → 편성 검수 → 렌더링. 계속 폴링 |
| 4900 \~ 4960 | 실패. 폴링 중단 |


### 편성 결과 통보

편성이 끝나면 접수 때 받은 `callback_url` 로 결과를 1회 POST 한다. 클립은 재생 순서이고, 좌표는 그 클립이 속한 파일(`stream_id` ) 기준 정수 초다. 드라마는 여러 회차에 걸칠 수 있어 항목마다 `v_id` 가 붙는다.

#### Request

```bash
[성공시]
POST {callback_url}
Content-Type: application/json

{
  "comp_id": 7,
  "query": "주인공 둘이 재회하는 장면",
  "result": "OK",
  "code": 0,
  "clips": [
    {
      "v_id": 1012,
      "stream_id": "VOD",
      "start_sec": 753,
      "end_sec": 768,
      "start_time": "00:12:33",
      "end_time": "00:12:48",
      "scene_seq": 3
    },
    {
      "v_id": 1015,
      "stream_id": "VOD",
      "start_sec": 2411,
      "end_sec": 2430,
      "start_time": "00:40:11",
      "end_time": "00:40:30",
      "scene_seq": 41
    }
  ]
}

[실패시]
{
  "comp_id": 8,
  "query": "주인공 둘이 재회하는 장면",
  "result": "fail",
  "code": -1,
  "clips": []
}
```

- 설명

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| comp_id | int | 접수 응답의 comp_id |
| query | str | 요청한 질의 원문 |
| result / code | str / int | `OK` / 0 성공 (장면 없음도 성공), `fail` / -1 실패 |
| clips[].v_id | int | 클립을 잘라 온 영상 |
| clips[].stream_id | str | 클립을 잘라 온 파일. VOD 는 `VOD` , 야구는 이닝 조각(`7top` 등) |
| clips[].start_sec / end_sec | int | 파일 기준 시작·끝 초 |
| clips[].start_time / end_time | str | 같은 값을 HH:MM:SS 로 |
| clips[].scene_seq | int | 드라마만. 파일 안 장면 번호 |
| clips[].text | str | 야구만. 이닝 (예: "5회초") |

#### Response

```bash
HTTP 200 OK
```
