### 들어가며

---

SBS 「나고야 아시안게임」 중계에서, 야구 경기 하이라이트를 AI 가 실시간으로 골라 실제 서비스에 내보낸 과정을 정리한 글이다.

SBS 는 2026 나고야 아시안게임(2026.09.19 \~ 10.04) 중계와 함께 **「AI PICK」** 이라는 영상 메뉴를 열었다.

- 대한민국 야구 경기가 진행되는 동안, 반 이닝(1회초, 1회말 …)이 끝날 때마다 그 이닝의 하이라이트 영상이 올라온다.
- 경기가 끝나면 경기 전체 하이라이트가 올라온다.
- AI PICK: [https://programs.sbs.co.kr/sports/ag2026/clips/90399](https://programs.sbs.co.kr/sports/ag2026/clips/90399)

우리 팀이 맡은 일은 **"어느 장면이 하이라이트인가"를 AI 로 골라 SBS 에 알려 주는 것** 이었다.

- 반 이닝이 끝나면 SBS 가 그 이닝의 중계 영상(mp4 파일)을 공용 S3 버킷에 올리고, 분석을 요청한다.
- 우리는 버킷에서 영상 파일을 받아 분석한다.
- 분석으로 그 이닝에 무슨 일이 있었는지(안타, 삼진, 득점 등) 정리한다.
- SBS 가 "하이라이트 장면 주세요" 라고 요청하면, 하이라이트로 쓸 장면의 시작·끝 시각을 골라 돌려준다.

이 글에 자주 나오는 말을 먼저 정리한다.

| 말 | 뜻 |
| --- | --- |
| 영상 파일 | 반 이닝 단위로 자른 중계 영상(mp4). 경기 하나가 영상 파일 9 \~ 18개로 나뉘어 들어온다 |
| 공용 S3 버킷 | SBS 와 함께 쓰는 클라우드 저장소. SBS 가 영상 파일을 올리면 우리가 받아 간다 |
| 전광판 | 중계 화면 구석에 나오는 점수판. 이닝, 점수, 볼카운트, 아웃, 주자가 표시된다 |
| 분류 | AI 가 이미지 전체를 보고 이름 하나를 붙이는 것 (예: "광고 화면") |
| 검출 | AI 가 이미지 안에서 물체의 위치를 상자로 찾는 것 (예: "전광판은 여기") |
| VLM | 이미지를 보고 글로 답하는 AI 모델. 전광판의 글자와 숫자를 읽고, 화면 종류를 판정하는 데 쓴다 |
| 보고 | 처리가 끝났을 때 우리 쪽에서 SBS 쪽으로 결과를 보내 주는 것 |

##### 1. 전광판을 읽는 AI 모델

- 하이라이트를 고르려면 먼저 **경기에서 무슨 일이 있었는지** 알아야 한다.
- 그 단서가 **전광판** 이다. 볼카운트가 바뀌면 공을 하나 던진 것이고, 아웃이 늘면 아웃을 잡은 것이고, 점수가 바뀌면 득점한 것이다.
- 그래서 영상을 1초에 한 장씩 사진(프레임)으로 뽑고, 사진마다 전광판을 찾아 읽는다.

**1-1. 사진 한 장을 읽는 과정**

- 사진 전체 → 전광판 → 전광판 안의 칸 → 칸의 글자 순서로 좁혀 들어간다.

![image](/img/achievement/2026년-나고야-아시안게임-야구-시범서비스/img-01.jpg)

| 단계 | 방법 | 하는 일 |
| --- | --- | --- |
| ① 야구 화면인가 | 분류 | 광고 화면을 걸러낸다 |
| ② 전광판은 어디인가 | 검출 | 사진에서 전광판 위치를 찾고, 그 부분만 잘라낸다 |
| ③ 어떤 전광판인가 | 분류 | 어느 방송사·대회의 전광판인지 고른다 |
| ④ 칸은 어디인가 | 검출 | 전광판 안에서 팀·이닝·볼카운트·아웃·주자 칸을 찾는다 |
| ⑤ 무엇이 쓰여 있나 | VLM | 칸마다 글자와 숫자를 읽는다 |

- ③ 이 필요한 이유는 **방송사마다 전광판 모양이 달라서** 다. 칸의 위치와 모양이 전광판마다 다르므로, ④ 는 전광판 종류마다 모델을 따로 둔다.
  - KBO 중계용 4종(KBS, MBC, SBS, SPOTV)에, 이번 대회를 위해 아시안게임 SBS 중계용 2종을 더했다.

- 실제 화면은 아래와 같다. 결승전 1회초, 경기 시작 2분 11초의 사진이다.

![image](/img/achievement/2026년-나고야-아시안게임-야구-시범서비스/img-02.jpg)

- 오른쪽 판정 결과에서 ① 은 "정상(야구)" 이고, ⑤ 가 읽은 값은 아래와 같다.

**1-2. AI 를 가르칠 데이터 만들기 — Roboflow**

- ①\~④ 의 AI 모델은 미리 **정답을 표시한 사진** 으로 학습시켜야 한다. 이 정답 표시 작업을 **라벨링** 이라고 한다.
- 라벨링에는 **Roboflow** 를 썼다. 사진을 올리고, 정답을 표시하고, 학습용 데이터로 묶어 내보내는 도구다.
- 학습 자체는 우리 서버에서 한다. Roboflow 에서는 데이터를 만들고 관리한다.

![image](/img/achievement/2026년-나고야-아시안게임-야구-시범서비스/img-04.jpg)

- 정답을 표시하는 방법은 모델 종류에 따라 다르다.
  - **검출** 모델용 사진에는 **상자를 그린다.** 프레임에는 전광판 상자를, 잘라낸 전광판에는 칸마다 상자를 그린다.

  - **분류** 모델용 사진에는 **이름 하나를 붙인다.** 전광판 사진마다 "AsianGame_SBS", "KBO_SBS" 처럼 종류 이름을 붙인다.

- **검출** 모델용 사진에는 **상자를 그린다.** 프레임에는 전광판 상자를, 잘라낸 전광판에는 칸마다 상자를 그린다.
- **분류** 모델용 사진에는 **이름 하나를 붙인다.** 전광판 사진마다 "AsianGame_SBS", "KBO_SBS" 처럼 종류 이름을 붙인다.

##### 2. SBS 와 주고받는 방식

- SBS 와 우리 시스템은 정해진 규칙(연동 규격)대로 요청과 결과를 주고받는다. 규격은 「외부 연동 규격-SBS」 문서에 있다.
  - [https://doc.scenemaker.solbox.com/docs/guide/1](https://doc.scenemaker.solbox.com/docs/guide/1)

- [https://doc.scenemaker.solbox.com/docs/guide/1](https://doc.scenemaker.solbox.com/docs/guide/1)
- 주고받는 일은 두 가지다.
  - **영상 등록/분석** — "버킷에 올린 이 영상 파일을 분석해 주세요"

  - **영상 검색** — "이 경기에서 하이라이트 장면을 골라 주세요"

- **영상 등록/분석** — "버킷에 올린 이 영상 파일을 분석해 주세요"
- **영상 검색** — "이 경기에서 하이라이트 장면을 골라 주세요"
- 두 요청 모두 **받았다는 응답만 바로 하고, 결과는 일이 끝난 뒤 따로 보낸다(보고).** SBS 는 결과를 기다리며 연결을 붙잡고 있지 않아도 된다.

**2-1. 영상 등록/분석**

![image](/img/achievement/2026년-나고야-아시안게임-야구-시범서비스/img-08.png)

- 야구는 경기 하나를 통째로 보내지 않고, 중계 중에 **반 이닝 영상 파일을 차례로** 보낸다.
- SBS 는 영상 파일을 공용 S3 버킷에 먼저 올리고, 그 위치를 담아 분석을 요청한다. 우리는 그 위치에서 파일을 받아 간다(그림의 2) 파일 Get).
  - 결승전 영상 파일은 하나에 150MB \~ 700MB 였다.

- 결승전 영상 파일은 하나에 150MB \~ 700MB 였다.

| SBS 가 보내는 것 | 뜻 |
| --- | --- |
| 경기 번호 | 경기 하나에 하나. 영상 파일이 여러 개여도 같은 번호를 쓴다 |
| 파일 위치 | 공용 S3 버킷에 올린 영상 파일의 위치 |
| 영상 번호 | 영상 파일마다 붙는 고유값. 실제 대회에서는 `20260927184704` 처럼 날짜·시각 형식이었다 |
| 마지막 표시 | 경기의 마지막 영상 파일에만 붙인다. 이후로는 그 경기의 영상 파일을 받지 않는다 |

- 분석이 끝나면 경기 번호와 영상 번호를 담아 "분석 완료" 를 보고한다.

**2-2. 영상 검색**

![image](/img/achievement/2026년-나고야-아시안게임-야구-시범서비스/img-09.png)

- 분석이 끝난 경기에 **찾고 싶은 장면을 문장으로** 보내면, 맞는 장면을 골라 준다.

| 주고받는 것 | 내용 |
| --- | --- |
| SBS → 우리 | 경기 번호, 찾고 싶은 장면 (예: "하이라이트 장면 주세요") |
| 우리 → SBS (바로) | 검색 번호. 실제 대회에서는 `20260927-1045-1` 처럼 날짜·경기·순번이었다 |
| 우리 → SBS (끝난 뒤) | 고른 장면 목록. 장면마다 시작·끝 시각과 이닝·사건 (예: "5회초 득점") |

- 대회에서는 장면 구간을 보고하고, 하이라이트 영상은 SBS 가 만들었다. 그래서 그림의 4) 파일 전달 단계는 쓰지 않았다.

**2-3. 시험과 분석 결과 확인**

- 대회 전(9월 10일 \~ 19일)에 시험 등록이 24건 있었다. 그중 11건은 2018 아시안게임 야구 중계 영상이다.
- 분석 결과는 검수 화면(workspace)에서 확인한다. 아래는 결승전의 **전광판 판독 결과** 다.

![image](/img/achievement/2026년-나고야-아시안게임-야구-시범서비스/img-10.jpg)

- 1초마다 읽은 이닝·점수·볼(B)·스트라이크(S)·아웃(O)·주자가 한 줄씩 쌓인다. 값이 바뀐 칸은 `0 → 1` 처럼 표시된다.
- 값이 바뀐 줄만 모으면 **경기 상태 기록** 이 된다.

![image](/img/achievement/2026년-나고야-아시안게임-야구-시범서비스/img-11.jpg)

- 볼넷으로 타자가 1루에 나가면 `타자1루` , 아웃이 늘면 `아웃` 처럼 사건 이름이 붙는다.
- 마지막으로 이 기록을 **장면** 으로 나눈다. 장면은 공 하나, 플레이 하나 단위의 영상 구간이다. 화면이 투구 장면인지, 수비 장면인지 같은 화면 종류는 VLM 이 판정해 함께 붙인다.

![image](/img/achievement/2026년-나고야-아시안게임-야구-시범서비스/img-12.jpg)

- 결승전 한 경기에서 장면 299개가 나왔고, 그중 사건(안타, 아웃, 진루 등)이 있는 장면이 89개다.
- 장면마다 이닝, 시작·끝 시각, 판정(볼, 스트라이크, 볼넷, 삼진 등), 사건, 점수, 볼카운트가 저장된다. SBS 가 하이라이트를 요청하면 이 장면들 중에서 고른다.

##### 3. 대회 기간 운영

- 대회 기간에는 대한민국 경기마다 아래 과정이 반 이닝마다 반복되었다.
1. 반 이닝이 끝나면 SBS 가 영상 파일을 공용 S3 버킷에 올리고 분석을 요청한다.
2. 우리가 영상 파일을 받아 분석하고 완료를 알린다.
3. SBS 가 그 이닝의 하이라이트를 요청한다.
4. 장면을 골라 시각을 알려 준다.
5. SBS 가 AI PICK 에 그 이닝의 하이라이트를 올린다.
- 경기가 끝나면 경기 전체를 대상으로 한 번 더 요청한다.
- 결승전(9월 27일, 대한민국 vs 일본)의 반 이닝별 처리 시간은 아래와 같다.

![image](/img/achievement/2026년-나고야-아시안게임-야구-시범서비스/img-13.jpg)

- 영상 파일 18개가 18:47 부터 21:54 까지 올라왔다.
- 영상 파일이 올라온 뒤 하이라이트 요청까지 **평균 3분** (짧게는 1분 46초, 길게는 4분 29초)이 걸렸다. 그 사이에 파일을 받고 분석을 마쳤다.
- AI PICK 영상은 **경기가 진행되는 중에** 올라왔다. 영상 파일이 올라온 뒤 게시까지 **평균 9.5분** (4.3 \~ 20.2분)이다.
  - 예) 1회초 영상 파일 18:47 업로드 → 하이라이트 요청 18:50 → AI PICK 「1회초 하이라이트」 18:56 게시

- 예) 1회초 영상 파일 18:47 업로드 → 하이라이트 요청 18:50 → AI PICK 「1회초 하이라이트」 18:56 게시
- 경기 종료 후 21:59 에 경기 전체 하이라이트 요청이 들어왔고, AI PICK 의 결승전 하이라이트는 22:17 에 올라왔다.
- 하이라이트 요청 문장은 아래와 같았다.

| 대상 | 요청 문장 |
| --- | --- |
| 반 이닝 | 하이라이트 장면 주세요 / 경기 흐름에 영향을 주는 중요한 하이라이트 장면만 뽑아줘 |
| 경기 전체 | 전체 하이라이트 뽑아줘 / 득점장면만 뽑아줘 / 대한민국의 안타 장면과 전체 득점 장면 뽑아주세요 |

- 경기 중 처리 상황은 운영 대시보드로 지켜봤다. 아래는 결승전 화면이다.

![image](/img/achievement/2026년-나고야-아시안게임-야구-시범서비스/img-14.jpg)

- 반 이닝마다 영상 파일이 올라온 시각, 처리 단계, 전광판을 찾은 비율, 고른 장면과 클립 수가 한 줄로 나온다.
- 결승전은 영상 파일 18개 모두 처리가 끝났고, 반 이닝 하이라이트로 **클립 87개** 를 보냈다.
- 전광판을 찾은 비율은 반 이닝마다 72% \~ 91% 였다. 중계 화면에는 전광판이 나오지 않는 장면도 있다.

#### 마무리

SBS 「나고야 아시안게임」 중계에서 대한민국 야구 5경기를 실시간으로 분석해, 반 이닝마다 하이라이트 장면을 골라 보냈다. SBS 는 이를 AI PICK 으로 내보냈다.

정리하면 아래와 같다.

- 1초마다 뽑은 사진에서 전광판을 찾고, 칸을 찾고, 글자를 읽어 경기 상태를 기록한다.
- AI 를 가르칠 데이터는 Roboflow 에서 만들었고, 아시안게임 SBS 전광판 데이터는 대회 직전에 따로 만들었다.
- SBS 가 공용 S3 버킷에 올린 영상 파일을 받아 분석한다. SBS 와는 "분석 요청"과 "장면 검색" 두 가지로 주고받는다. 둘 다 요청을 받으면 바로 응답하고, 끝나면 결과를 보낸다.
- 결승전 기준으로 반 이닝 영상 파일이 올라오면 평균 3분 뒤 하이라이트가 요청되었고, 평균 9.5분 뒤 AI PICK 에 영상이 올라왔다.
- 5경기, 영상 파일 78개, 하이라이트 요청 96건을 처리했고 실패는 없었다. AI PICK 영상은 80개가 올라갔다.
