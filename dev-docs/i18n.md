# i18n 구조

> [CLAUDE.md](../CLAUDE.md) 허브에서 분리한 상세 문서. 한국어 원본 / 영어 번역 구조, symlink 방향, EN 파일 추가 규칙.

**한국어가 원본, 영어는 번역본.**

| 경로 | 역할 |
|------|------|
| `docs/` | KR 원본. Notion 자동 동기화 대상. |
| `docs_en/` | EN 번역본 편집 위치. **실제 파일이 여기 있다.** |
| `i18n/en/.../current` | `docs_en/`을 가리키는 심볼릭 링크. Docusaurus가 읽는 경로. |

## 주의: symlink 방향

```
i18n/en/docusaurus-plugin-content-docs/current  →  ../../../docs_en
```

- `docs_en/` = 실제 파일
- `i18n/.../current` = symlink

**반대로 하면 안 된다.** webpack이 symlink를 real path로 resolve해서 Docusaurus SSG 라우팅과 불일치 → DocItem `content` props undefined 오류 발생. `docusaurus.config.ts`의 `resolve.symlinks: false` 플러그인이 이 문제를 해결한다 (방향이 맞더라도 적용 중).

## EN 파일 추가 규칙

1. `docs/section/filename.md`에 KR 파일이 있으면 → `docs_en/section/filename.md` 에 EN 번역 추가
2. EN 파일 frontmatter에 `slug: "N"` 반드시 포함 (KR과 동일한 값)
3. EN 파일에 `id:` 필드는 넣지 않는다 — `translate_to_en.py`가 자동으로 제거하며, Docusaurus가 파일 경로로 KR/EN 매칭
4. `sidebar_position:` 은 KR과 동일하게
5. **`docs_en/` 파일명은 KR 파일명과 반드시 동일해야 한다** — Docusaurus가 파일 경로 기준으로 KR/EN 페이지를 매칭하므로 이름이 다르면 로케일 스위처가 깨짐
   - KR: `docs/poc/poc-기획안-멀티모달-llm.md` → EN: `docs_en/poc/poc-기획안-멀티모달-llm.md` (동일 파일명 필수)
   - Notion 동기화로 KR 파일명이 변경되면 EN 파일명도 반드시 함께 변경할 것
   - `translate_to_en.py`가 자동으로 처리하지만, 수동으로 EN 파일 생성 시에도 동일하게 적용

> UI 라벨(네비/푸터/사이드바 카테고리)은 `i18n/en/`의 JSON으로 따로 번역한다. KR 원본 라벨 변경 후엔 `npm run write-translations:en`으로 골격을 갱신한다.
