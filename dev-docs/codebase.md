## URL 구조 (slug 시스템)

Notion 동기화 파일은 `slug: "N"` frontmatter로 숫자 URL을 갖는다.

```
docs/architecture/아키텍처-설계.md  (slug: "1")  →  /docs/architecture/1
docs/install/qwen-3x-설치.md       (slug: "1")  →  /docs/install/1
docs/install/llm-설치.md           (slug: "2")  →  /docs/install/2
```

**계층 구조 페이지 (Notion 하위 항목이 있는 경우):**

```
docs/poc/vision-bench/_category_.json  (generated-index, slug: "/poc/vision-bench")  →  /docs/poc/vision-bench
docs/poc/vision-bench/child.md         (slug: "1")                                    →  /docs/poc/vision-bench/1
```

- 카테고리 인덱스 URL은 `_category_.json`의 `"link": {"type": "generated-index", "slug": "/{section}/{subdir}"}` 가 담당
  - ⚠️ `slug: "/"` 사용 금지 — 절대경로(`/docs/`)로 해석되어 Duplicate routes 발생
- 부모 `index.md`는 Notion 페이지에 본문 내용이 있을 때만 생성됨 (없으면 자동 삭제)
- 자식 파일은 `slug: "{child-order}"` (부모 디렉토리 기준 상대 슬러그)
- **slug는 섹션 내 상대경로**. `"architecture/1"` 같은 전체 경로 쓰면 안 된다.
- 새 파일은 섹션 내에서 `sidebar_position` 순서에 맞춰 다음 번호를 부여한다.
- **Notion 동기화 파일**: `scripts/notion_to_md.py`가 `slug` 자동 생성. 수동 추가 파일만 직접 slug를 넣어야 한다.

## 빌드 게이트

### CI에서 실패하는 것
- **깨진 내부 링크** — `onBrokenLinks: 'throw'` 설정. PR 전 `npm run build` 통과 필수.
- **MDX 컴파일 오류** — 프론트매터·JSX 문법 오류.

> PR 단위 자동 검증은 `.github/workflows/pr-build.yml`(main·develop 대상)이 담당한다. 배포는 `deploy.yml`(main push).

### 로컬에서만 확인
- `npm run typecheck` — `strict: true`지만 빌드와 무관. IDE 보조용.

## 콘텐츠 추가 워크플로우

### 새 Notion 섹션 추가 시

1. `secrets.NOTION_XXX` 시크릿 등록
2. `scripts/server-sync.sh`에 새 DB 환경변수 블록 추가
3. `docs/new-section/` 디렉토리 및 `_category_.json` 생성
4. `sidebars.ts`에 새 사이드바 항목 추가
5. `docusaurus.config.ts` navbar에 `{type: 'docSidebar', ...}` 추가

### 수동으로 새 문서 추가 시

1. `docs/section/filename.md` 생성 (slug, sidebar_position, title 포함)
2. `npm run build` 통과 확인 후 main에 push
