### Introduction

---

This post summarizes the status of my contributions to the open-source projects I’ve worked on while developing SceneMaker. I covered where to find opportunities to contribute and the order in which to submit them in the “Comprehensive Guide to Open-Source Contributions.” This post covers **what I contributed, how many contributions there were, and their current status**. The status was verified again on GitHub on October 30, 2026.

![image](/img/notes/오픈소스-생태계-기여-실적-보고-1건/img-00.jpg)

- There have been **31** contributions from other developers: 14 pull requests, 10 issues, and 7 discussions. The project’s goal is 30 contributions.
- All 14 pull requests have been merged, and **11 of them have already been included in a released version.** The remaining 3 will be included when the project releases its next version.
- There are 17 more pull requests awaiting merge. Since they haven’t been merged yet, they aren’t included in the figures above.

---

#### 1. What Counts as a Contribution

When counting contributions, we only count **those in which other developers actually participated**. We do not count submissions that were simply uploaded without any response.

- **Pull Request:** One that has been reviewed and merged by a maintainer
- **Issue:** One that has been closed as resolved by a maintainer, or where another developer has helped identify the cause or taken responsibility for the fix
- **Discussion:** One to which a maintainer or another developer has replied

The 17 pull requests currently under review and the 5 pull requests closed without being merged are not counted. Excluding the 2 external issues currently in progress (where another developer has submitted a fix pull request and it’s under review), the total number of resolved items is 29.

---

#### 2. Contributions came from tools used by the pipeline

I didn’t specifically look for places to contribute. All the repositories I contributed to are tools actually used by the SceneMaker pipeline.

![image](/img/notes/오픈소스-생태계-기여-실적-보고-1건/img-01.jpg)

- **Audio:** Transcription (faster-whisper, whisper), language detection (SpeechBrain), audio file reading (python-soundfile)
- **Video:** Scene segmentation (PySceneDetect), frame image processing(Pillow)
- **Inference:** Model serving (vLLM), model invocation (LiteLLM)
- **Indexing:** Vector search (Milvus)
- **Service:** API server (Starlette, Uvicorn, AnyIO), configuration and validation (pydantic, pydantic-settings), DB connection (PyMySQL)

Since I wrote these tools myself, I knew the exact conditions under which issues actually occurred, and this knowledge was directly applied to creating reproduction examples and tests.

#### 4. 10 Issues

- **6 closed as resolved**
  - [vLLM — Issue where videos without frame count information are read as 1 frame](https://github.com/vllm-project/vllm/issues/60518): Within a few hours of posting, another developer submitted a fix pull request, which was merged, resolving the issue.

  - [PySceneDetect — Regression where cuts shorter than the minimum scene length are discarded in 29.97 fps videos](https://github.com/Breakthrough/PySceneDetect/issues/577): The maintainer expressed gratitude for the reproduction and fix and incorporated it into the next version.

  - [SpeechBrain — Issue where the saved file name is ignored with a specific download method](https://github.com/speechbrain/speechbrain/issues/3091) : This was resolved when the pull request I submitted was merged.

  - [PyMySQL — Issue where enabling server authentication alone causes an error during SSL configuration](https://github.com/PyMySQL/PyMySQL/issues/1281) : The maintainer fixed and closed the issue.

  - 2 issues in the company repository: I resolved and closed pipeline issues reported by a colleague.

- **1 issue automatically closed**
  - [vLLM — 400 error due to cache conflict in requests using audio from videos](https://github.com/vllm-project/vllm/issues/44538): This was an issue raised by a colleague. Several developers investigated the cause together, but after a period of inactivity, the cleanup bot closed it.

- **3 issues in progress**
  - [pydantic — Issue where the JSON Schema for functions declared in a specific way contradicts the actual validation rules](https://github.com/pydantic/pydantic/issues/13938): Another developer has confirmed the issue, submitted a fix PR, and it is currently under review.

  - [LiteLLM — Issue where a prompt listing token IDs is rejected before the request is made](https://github.com/BerriAI/litellm/issues/45253): Another developer identified the cause, submitted a fix PR, and it is currently under review.

  - 1 issue in the company repository: An issue where the list of chunk files becomes misaligned when a video length ends in a decimal; a resolution path has been determined, leading to work on the relevant feature.

#### 5. 7 Discussions

All 7 received responses from people.

- **3 replied to by the maintainer**
  - [Pillow — Behavior where the cropping size varies depending on the position when the `crop()` coordinates end in .5](https://github.com/python-pillow/Pillow/discussions/10242): The maintainer provided a link to a similar case, and this discussion led to a fix PR that is currently under review.

  - [PySceneDetect — Merging behavior where a single short scene at the beginning pushes or removes a cut much later in the sequence](https://github.com/Breakthrough/PySceneDetect/discussions/585) : Another developer reproduced the issue, and the maintainer asked that it be reported as a bug.

  - [Milvus — Experience indexing video highlights by time intervals rather than text fragments](https://github.com/milvus-io/milvus/discussions/53969): A core developer proposed an alternative design that groups and stores data by time intervals.

- **4 cases answered by other developers**
  - [Uvicorn — Issue where all responses fail due to a space after the colon in the --header value](https://github.com/Kludex/uvicorn/discussions/3188)

  - [whisper — Issue where punctuation within words splits them in word-based timestamps](https://github.com/openai/whisper/discussions/2875)

  - [Starlette — Issue where deleting a non-existent attribute from a State raises a KeyError instead of an AttributeError](https://github.com/Kludex/starlette/discussions/3644)

  - [AnyIO — Issue where a task isn’t canceled even after calling `from_thread.run()` on a thread after the task was previously canceled](https://github.com/agronholm/anyio/discussions/1427)

  - All four issues were reproduced in the latest code by other developers, or the root cause was identified and confirmed.
