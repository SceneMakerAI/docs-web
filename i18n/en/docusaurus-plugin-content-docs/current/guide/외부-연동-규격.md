## Video Groups

A video group is a unit that bundles videos. A single TV series or a single baseball game constitutes one group, and videos are organized under it by episode (`order_no`). Categories (`cate_id`) and completion callbacks (`callback_url`) are attributes of the group, not of the individual videos.

Example: If there is “Manager Kim (Episodes 1–10),” then “Manager Kim” is the video group, and “Manager Kim – Episode 1” and “Manager Kim – Episode 2” are the individual videos within it.

| `POST` | `http://<host>:<port>/api/v1/video_group` | Register group. Returns an `v_g_id` |
| --- | --- | --- |
| `PUT` | `http://<host>:<port>/api/v1/video_group` | Modify group. Full replacement method |

### Create Video Group

#### Request

- Example

```bash
POST http://{HOST}:{PORT}/api/v1/video_group
Content-Type: application/json

{
  "cate_id": 5100,
  "name": "2026 KBO Regular Season",
  "callback_url": "http://sbs.co.kr/",
  "comment": "Regular Season"
}
```

- Description

| Field | Required | Type | Size | Description |
| --- | --- | --- | --- | --- |
| cate_id | Required | int | - | Category ID |
| name | Required | str | 1–100 | Group name |
| callback_url | Optional | str | 200 | URL to be notified when the entire group process is complete |
| comment | Optional | str | 200 | Remarks |

#### Response

```bash
{"code": 0, "result": "OK", "v_g_id": 12}
```

## Video Title

A video is the unit of analysis. A single episode of a drama or a single baseball game constitutes one video, and it is listed as an episode (`order_no`) under a video group (`v_g_id`). Name, broadcast year, and stream status (`stream_yn`) are attributes of the video, while the category and callback follow those of the group. The actual video file is attached to this `v_id` during the STT request (`stt_svc`).

Example: The “Manager Kim” group contains the videos “Manager Kim – Part 1” (`order_no` 1) and “Manager Kim – Part 2” (`order_no` 2). For baseball, one game constitutes a group, and there is one video per game.

| POST | http://<host>:<port>/api/v1/video | Register a video. Returns a v_id |
| --- | --- | --- |
| PUT | http://<host>:</host>/api/v1/video<host><port>

| Update a video. Partial replacement method |

- Description

| --- | --- | --- | --- | --- |

## Video Analysis

Register the video file and start the analysis process. This is the final step in the sequence: Group Registration → Video Registration → Video Analysis. When you associate the actual file (S3 object key) with a previously registered video (`v_id`), the process proceeds to download → audio and frame extraction → subtitles (STT). Since the title, category, year, and callback are already specified in the group and video, they are not accepted here.

Example) **Dramas are VOD**. Attaching a single file to the “Manager Kim – Episode 1” video (`v_id` 1012) completes the process; `stream_id` is not provided.  
**Professional baseball is streamed**. For a single game video (`v_id` 2001), segments such as top of the 1st inning, bottom of the 1st inning, top of the 2nd inning, etc., are received in sequence. Call this API once for each segment and separate them with `stream_id` (`1top`, `1bot`, `2top`, …). Set `last_yn` to Y only for the final segment (bottom of the 9th inning or end of extra innings).

| POST | **http://<host>:<port>

/api/v1/video_file** | **Upload video file + Start analysis** |
| --- | --- | --- |

### Video Title Generation

#### Request

- Example (Drama, VOD)

```bash
POST http://{HOST}:{PORT}/api/v1/video_file
Content-Type: application/json
{
  "v_id": 1012,
  "file_path": "vod/2/202.mp4",

```

- Example (Professional Baseball, Stream)

```bash
POST http://{HOST}:{PORT}/api/v1/video_file
Content-Type: application/json
{
  "v_id": 1012,
  "file_path": "vod/2/202_1top.mp4",
  "stream_id": "1top",
  "last_yn": "N",
  "forced_yn": "Y"
}
```

- Description

| Field | Required | Type | Size | Description |
| --- | --- | --- | --- | --- |
| v_id | Required | int | - | Video ID. Value issued during video title generation |
| file_path | Required | str | 5–200 | S3 object key. Do not include “s3://bucket/” |
| stream_id | Optional | str | 20 | Required for streamed video (set to “Y” for stream_yn). Omit for VOD |
| last_yn | Optional | str | 1 | Set to “Y” if this is the last segment. Set to “Y” for VOD. Default: “Y” |
| forced_yn | Optional | str | 1 | If “Y,” delete already-registered segments and reprocess. Default: “Y” |

#### Response

```bash
{"v_id": 1012, "stream_id": "VOD", "code": 0, "result": "OK"}
```

## Video Search (Extracting Analysis Content)

Submit a query to a video that has been analyzed to select scenes and compile them into highlights. The compilation unit is a group (`v_g_id`). For dramas, selections are made from the entire series (multiple episodes); for baseball, from a single game. If `videos` is provided, only that video (and its clips) within that group are targeted; if not, the entire group is targeted. Since compilation takes 1–3 minutes, the system only acknowledges receipt and responds immediately; completion is confirmed via a `callback_url` notification or a status inquiry.

Example: If you submit a query for “reunion scenes” to the “Manager Kim” drama group (`v_g_id`), the system will select from all episodes 1 through 10. If you submit a query to the baseball game group (`v_g_id` ) using `videos` to specify only clips from the 7th inning onward (`stream_id_1` , `stream_id_2` …), the system will select clips from within that inning.

| POST | http://<host>:<port>/api/v1/compose | Schedule submission. comp_id issued immediately |
| --- | --- | --- |
| GET | http://<host>:</host>/api/v1/status_compose?comp_id=<host><port>

| Check scheduling status. |

### Scheduling request accepted

#### Request

- Example (Drama, Entire Group)

```bash
POST http://{HOST}:{PORT}/api/v1/compose
Content-Type: application/json

{
  "v_g_id": 12,
  "query": "A scene where the two main characters reunite",
  "budget_sec": 180,
  "callback_url": "http://sbs.co.kr/"
}
```

- Example (Professional Baseball, Segment Specification)

```bash
POST http://{HOST}:{PORT}/api/v1/compose
Content-Type: application/json

{
  "v_g_id": 30,
  "videos": [
    {"v_id": 2001, "stream_ids": ["7top", "7bot", "8top", "8bot", "9top", "9bot"]}
  ],
  "query": "Only comeback scenes",
  "budget_sec": 90,
  "callback_url": "http://sbs.co.kr/"
}
```

- Description

| Field | Required | Type | Size | Description |
| --- | --- | --- | --- | --- |
| v_g_id | Required | int | - | ID of the group to be scheduled |
| videos | Optional | list | 1– | List of target videos. If omitted, all videos in the group |
| videos[].v_id | Required | int | - | Video ID. Must belong to that group |
| videos[].stream_ids | Optional | list[str] | 20 | List of segments (stream_ids). If omitted, all files in that video |
| query | Required | str | 1–200 | Describe the scene you want to find in a sentence. Examples: "home run," "comeback scene," etc. |
| budget_sec | Optional | int | - | Target duration (seconds). If omitted, no clipping will be performed |
| callback_url | Optional | str | 200 | URL to receive notification when compilation is complete |

#### Response

```bash
{"comp_id": 7, "code": 0, "result": "OK"}
```

Rejections are indicated by the HTTP status code, and the body contains the request key + reason (`reason`) + `code` -1 / `result` "fail".

| Situation | HTTP | Body |
| --- | --- | --- |
| No group | 404 | `{"v_g_id": 12, "reason": "영상 그룹이 없습니다.", "code": -1, "result": "fail"}` |
| No video or clip | 404 / 422 | `{"v_g_id": 12, "v_ids": [1099], "reason": "그룹에 속하지 않은 영상이 있습니다.", "code": -1, "result": "fail"}` |
| Analysis incomplete | 422 | `{"v_g_id": 12, "files": [{"v_id": 1012, "stream_id": "VOD", "status_code": 2011}], "reason": "분석이 끝나지 않은 영상이 있습니다.", "code": -1, "result": "fail"}` |
| Scheduling in Progress (Exceeded Threshold) | 409 / 429 | `{"v_g_id": 12, "reason": "편성이 진행 중입니다. 잠시 후 다시 요청해 주세요.", "code": -1, "result": "fail"}` |
| LLM Server Unavailable | 503 | `{"v_g_id": 12, "reason": "LLM 서버를 사용할 수 없습니다. 잠시 후 다시 요청해 주세요.", "code": -1, "result": "fail"}` |
| Request Format Error | 422 | Standard Validation Error |

### Check Scheduling Status

Use the `comp_id` in the response to check the progress status. `code` / `result` indicate whether the query itself was successful, while the scheduling status is indicated by `status_code` / `status_name`.

#### Request

```bash
GET http://{HOST}:{PORT}/api/v1/status_compose?comp_id=7
```

#### Response

```bash
[In Progress]
{"comp_id": 7, "code": 0, "result": "OK", "status_code": 4020, "status_name": "Selecting a scene"}

[Completed]
{"comp_id": 7, "code": 0, "result": "OK", "status_code": 4000, "status_name": "Highlighting complete"}

[Failure]
{"comp_id": 8, "code": 0, "result": "OK", "status_code": 4900, "status_name": "Scheduling Failed"}

[No recipient]
{"comp_id": 9, "code": -1, "result": "fail"}
```

| status_code | Meaning |
| --- | --- |
| 4000 | Complete. Results are notified via callback |
| 4001 | Complete. No scenes matching the criteria (empty list of clips) |
| 4010–4050 | In progress. Evidence indexing → Scene selection → Clip composition → Playlist review → Rendering. Continue polling |
| 4900–4960 | Failure. Stop polling |

### Playlist result notification

Once editing is complete, the results are posted once to the `callback_url` received at the time of submission. Clips are listed in playback order, and coordinates are integer seconds relative to the file (`stream_id`) to which the clip belongs. Since a drama may span multiple episodes, each entry is prefixed with `v_id`.

#### Request

```bash
[If successful]
POST {callback_url}
Content-Type: application/json

{
  "comp_id": 7,
  "query": "A scene where the two main characters are reunited",
  "result": "OK",
  "code": 0,
  "clips": [
    {
      "v_id": 1012,
      "stream_id": "VOD",
      "start_sec": 753,
      "end_sec": 768,
      "start_time": "00:12:33",
      "end_time": "00:12:48",
      "scene_seq": 3
    },
    {
      "v_id": 1015,
      "stream_id": "VOD",
      "start_sec": 2411,
      "end_sec": 2430,
      "start_time": "00:40:11",
      "end_time": "00:40:30",
      "scene_seq": 41
    }
  ]
}

[In case of failure]
{
  "comp_id": 8,
  "query": "The scene where the two main characters reunite",
  "result": "fail",
  "code": -1,
  "clips": []
}
```

- Description

| Field | Type | Description |
| --- | --- | --- |
| comp_id | int | comp_id from the submission response |
| query | str | Original text of the requested query |
| result / code | str / int | `OK` / 0 Success (including “No scene” as a success), `fail` / -1 Failure |
| clips[].v_id | int | Video from which the clip was extracted |
| clips[].stream_id | str | The file from which the clip was extracted. For VOD, `VOD`; for baseball, inning segments (`7top`, etc.) |
| clips[].start_sec / end_sec | int | Start and end seconds relative to the file |
| clips[].start_sec / end_sec | int | Start and end seconds relative to the file |
| clips[].start_time / end_time | str | Same values formatted as HH:MM:SS |
| clips[].scene_seq | int | For dramas only. Scene number within the file |
| clips[].text | str | For baseball only. Inning (e.g., "Top of the 5th") |

#### Response

```bash
HTTP 200 OK
```
