## 1. Introduction

In Part 2 (OFAT Sweep), we established the `temperature 0.7 · 페널티 off · dedup ON` combination based on **conformity** criteria that allow for evaluation without a reference answer key. This part addresses the next question: **how accurate is the output (quality)?**

Since this is data without answer labels, we use a top-tier model as a benchmark and conduct validation as follows:

1. Create a Gemini answer key (reference) under optimal conditions.
2. Score Qwen’s output for the same task using LLM-judge.
3. Quantify the impact of penalty size on quality, as noted in Part 2, as well as the limitations and improvement directions for Qwen’s quality.
   - Fine-tuning of the fps and thinking levers will be conducted

> in subsequent measurements 💡 **Note**: The scores in this paper are not absolute answers but rather **"matching accuracy relative to the best benchmark (Gemini)"**. We present the score of a commercial model (gemini-3.5-flash) graded using the same criteria to serve as a reference point for interpreting Qwen’s scores.

#### **Rationale for Using gemini-3.1-pro as the Answer Key and Grader**

- **Official Positioning**: This is the latest version in the current Pro line, announced by Google as its “most advanced reasoning model.” (Released in February 2026; the previous gemini-3-pro has been deprecated and replaced by this ID). [Google Official Announcement](https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-3-1-pro/)
- **Advantage in Reasoning Benchmarks**: While Flash (3.5) outperforms 6 out of 8 public benchmarks, these are all in the areas of speed, agent tasks, and practical applications; **in the two most difficult pure reasoning benchmarks (ARC-AGI v2 77.1% · Humanity’s Last Exam), 3.1-pro holds the advantage**. [LLM-Stats Comparison](https://llm-stats.com/models/compare/gemini-3.1-pro-preview-vs-gemini-3.5-flash)
- **Role Suitability**: The answer key is “the eye that reads the video most accurately,” and scoring involves “careful judgment of the semantic correspondence between two texts”—both of which are tasks determined by the quality of inference rather than speed. This is why we assigned the task to the inference-based (pro) category rather than the practical/speed-based (flash) category.
- **Prioritizing Information in the Answer Key**: Regardless of model selection, the answer key provides maximum information at 24 fps (144 frames) and high resolution, establishing the principle that **"Best Model + Maximum Information = Strongest Standard"** . As confirmed by the empirical comparison in §3.1, even the same model produces different output precision depending on the input information.

### 2.2. Scoring Method — Standardization to LLM-judge

**"Even if the wording differs, it is considered correct if the context and meaning match"** Since the output is a generated sentence, exact string matching is inherently impossible, and modifying and reapplying scoring criteria is cheapest when done through prompt adjustments.

For each clip, the judge receives the answer key and candidate outputs and calculates the following three values **for each field**.

| **Calculation** | **Meaning** |
| --- | --- |
| `score` (integer 0–5) | 5 = Perfect semantic match; 0 = Irrelevant or entirely hallucinated. **Explicitly specified that hallucinations result in a larger penalty than omissions** |
| `missed` | Items present in the answer key but with no semantic match in the candidate list (omissions = loss of recall) |
| `hallucinated` | Items present in the candidate set but with no semantic correspondence in the answer key (hallucination = precision loss) |

> Since the graders do not view the video directly, “hallucinated” strictly speaking does not mean “hallucination” but rather **“not present in the answer key”**. We created the answer key under optimal conditions (24 fps, high resolution) to reduce this gap, and the remaining limitations are verified in §5.

### 2.3. Final Score

**Final Score = Average of 6-field scores per clip → Average of all 70 clips (0–5).** Clips that fail schema validation are included in the denominator with a score of 0—settings with frequent failures automatically have their scores reduced. We did not apply any composite formulas such as weights or gates. The severity of hallucinations and omissions is already reflected in the score via the scoring rubric, and since the original text for all “missed” and “hallucinated” items is saved, if other criteria (e.g., precision-weighted F-score) become necessary, they can be **calculated retrospectively without re-scoring** .

## 3. Testing

### 3.1. Building the Answer Key — Upgrading from Flash to Pro

Initially, we created the answer key using the GA stable version, gemini-3.5-flash (fps 1). However, the issue that **“even the baseline model can make mistakes”** remained, so we upgraded the ground truth to **the best model + maximum information** (gemini-3.1-pro · fps 24 · high resolution) and downgraded the flash output to the evaluation target (control group candidate). Actual comparison of the two answer key candidates:

| **Answer Key Candidate** | **ok/fail** | **Total Visual Items (objects/ocr/actions)** | **Audio Presence Rate (bgm/sfx)** |
| --- | --- | --- | --- |
| flash · fps 1 | 70/0 | 393 / 219 / 235 | 72.9% / 61.4% |
| **pro · fps 24 (selected)** | 70/0 | **465 / 309 / 268** (OCR +41%) | 61.4% / 50.0% |

> The pro answer key is overwhelmingly accurate in terms of visual cues (especially screen text and scoreboard details) but is **more conservative regarding auditory cues**. The distortion this asymmetry causes in scoring is discussed in §5.

### 3.2. Candidate Settings — 5 Types

| **Candidate** | **Key Parameters** | **Purpose** |
| --- | --- | --- |
| base | temp 0.7 · penalty off (2-part fixed combination) | Starting point |
| freq 0.3 | base + frequency_penalty 0.3 | 1D sweep of penalty magnitude |
| freq 0.5 | base + frequency_penalty 0.5 | 1D sweep of penalty magnitude |
| Reproduction of Case 03 | temp 0.0 (greedy) + freq 1.1 | Operational values from Part 1 — Measuring the trade-off between quality and "failure 0" settings |
| flash | gemini-3.5-flash · fps 1 | Control group (commercial model baseline) |

Common fixed settings: Same 70 clips (7 genres × 10) · Same prompt and schema · max_tokens 512 · Audio on. The fps and thinking sliders are separated for subsequent measurements.

### 3.3. Execution Pipeline

Three-stage structure in the experiment directory `experiments/03_param_tuning_quality_eval/` — `run.py` (Qwen measurement) → `run_gemini.py` (answer key generation) → `judge.py` (scoring and aggregation, 6-way parallel). The outputs are separated into `results/` (candidate output) · `gold/` (answer key cache) · `scores/` (scoring).

```bash
# Generate Answer Key 1 (Fixed Cache)
python run_gemini.py ../../data/sample70 --model gemini-3.1-pro-preview --fps 24 --media-resolution high -o gold/gemini31pro.json
# Candidate Measurement (by Setting)
python run.py ../../data/sample70 -o results/qwen_base.json
# Grading (Answer Key vs. Candidate's Answers)
python judge.py gold/gemini31pro.json results/qwen_base.json -o scores/qwen_base.json
```

## 4. Results

### 4.1. Reaffirmation of Conformity — The Auditory Cost of Penalties

The findings from Part 2 were replicated on the same sample. Penalties eliminate failures, but they do so by **emptying the auditory information**.

| **Settings** | **ok/fail** | **repeat** | **BGM presence rate** | **SFX presence rate** |
| --- | --- | --- | --- | --- |
| base (0.7 · penalty off) | 69/1 | 18.6% | **50.7%** | **44.9%** |
| freq 0.3 | 70/0 | 8.6% | 28.6% | 32.9% |
| freq 0.5 | 70/0 | 2.9% | 22.9% | 22.9% |
| Reproduction of Case 03 (greedy + freq 1.1) | **70/0** | 5.7% | 8.6% | 12.9% |

> The "0 failures" in Reproduction of Case 03 is accurate. However, only 6 out of 70 BGM clips remain — This is not because there are no defects, but because the structure **produces fewer outputs, leaving no opportunity for defects to occur**. The 18.6% repeat rate in the base model is not a cost, as the deduplication post-processing removes it without loss.

### 4.2. Initial Scoring Results (N=1)

| **Candidate** | **Final Score (0–5)** | **Missed** | **Hallucinated** |
| --- | --- | --- | --- |
| **gemini-3.5-flash (control group)** | **3.20** | 533 | 354 |
| qwen freq 0.3 | 2.33 | 863 | 453 |
| qwen rep03 | 2.29 | 897 | **307** |
| qwen base | 2.22 | **799** | 655 |
| qwen freq 0.5 | 2.20 | 906 | 442 |

#### 1. The benchmark itself is strict — Qwen ≈ 70% of Flash

Even a top-tier Flash score is **3.20/5**. Since this is based on the “Ultimate Answer Key” (24 fps), achieving a perfect score is structurally difficult. A Qwen score of 2.2–2.3 should not be interpreted as an absolute value, but rather as **“approximately 70% of Flash’s level”**.

#### 2. Genre patterns support the FPS hypothesis

Qwen’s performance drops in fast-paced genres (esports 1.82 · drama 1.88 · baseball 1.98), but in static historical dramas, it reaches 3.0, approaching flash (3.5). flash remains consistent across all genres at 3.0–3.5. **A signal that 3 frames (0.5 fps) cannot keep up with dynamic scenes**—this is a key point to watch in subsequent fps measurements.

#### 3. Sampling is not a quality lever

Hallucinations decreased in a dose-response manner with penalties (base 655 → old 03 307), while omissions increased in the opposite direction (799 → 906), revealing the trade-off in numerical terms. However, **the final score gap between settings is only 0.13**. No sampling combination can break through the quality ceiling (~2.3) — the core determinants of quality are model size and input information density, and the role of sampling tuning was already covered in Part 2(Adaptation).

## 5. Scoring Verification and Limitations

Rather than taking the scoring results at face value, we performed a triple cross-check (manual verification) of the answer key, candidate outputs, and scoring details using sample clips.

#### Justified point deductions — Qwen’s actual weaknesses

- **"actions" describe the camera view, not the content** — Correct answer: "turning pages · using sign language" vs. Qwen: "showing · analyzing · being inserted" (score 0 justified)
- **Adjectives describing atmosphere rather than sound for **bgm**** — “trustworthy,” “formal” (hallucination judgment justified)
- **Omission of visual details** — sign language interpreter, keyboard, etc. (3-frame limit)

#### Scoring Bias — 3 Correctable Issues

- **① Scoring without dedup** — Exact duplicates in candidate outputs (“KBS NEWS” ×2) were counted as hallucinations. These should have been removed before scoring, in accordance with the final pipeline (dedup ON).
- **② Double-counting of OCR segmentation units** — When the same text is segmented differently (“2018 Ulsan District Prosecutors’ Office” vs. “2018 Ulsan District Prosecutors’ Office **cited**”), it is counted simultaneously as both “missed” and “hallucinated”
- **③ Audio-Blank Answer Key Distortion** — Since the pro answer key is conservative regarding audio (50% SFX presence rate), candidates that include plausible sounds (e.g., “game music” in esports) receive at least 0 points, while **leaving the field blank results in a blank-to-blank match worth 5 points**. A structural bias that favors silent scenarios

> Bias ③ works in favor of the penalty setting (the side with less auditory output). **The first-place ranking (freq 0.3 > base, gap 0.11) falls within this distortion range, so it is provisional until the bias-corrected re-grading is complete**.

#### Structural Limitation — “Same Family” Grading

This is a **“same family” grading structure** where the answer key, the grader, and Control Group 2 all belong to the same model (Control Group 1 is also from the Gemini series). Since the expression habits resemble those of the answer key written by the same model, this may be advantageous for semantic matching, making it structurally likely that Gemini-series candidates (control group) will receive higher scores. The grading criteria (“correct if the meaning matches, even if the wording differs”) help mitigate this, and the robustness of the rankings can be verified by cross-grading a small sample with a different grader (flash).

## 6. Next Steps

- **Re-grading after correcting scoring bias** — Apply dedup · Allow partial OCR matches · Mitigate discrepancies between audio and answer sheets → Finalize rankings
- **FPS (1.0 · 2.0) · Thinking Measurement** — The key quality lever indicated by genre patterns. Operated at a measured latency level of +5–32% (3.7→4.9 seconds per clip), which does not impose operational constraints
- **Human review of a sample** — Calibrate answer key reliability (10–20 clips)
- **Implications** — The key to quality improvement lies not in sampling, but in **input data volume (fps) · thinking · model scale**
