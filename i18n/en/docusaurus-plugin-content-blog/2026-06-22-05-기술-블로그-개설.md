### Introduction

---

  
This blog is the **official technical blog of the Solbox Inc. SceneMakerAI project**, which repurposes broadcast content using open-source AI technology.   

  
  
<!--truncate-->

During the development process, we decided to publish a blog post every month. While we had already decided to write the posts in Notion, we were unsure how to publish them publicly. After testing several options (Velog, Tistory) simultaneously, we ultimately chose **Docusaurus**.  

![image](/img/blog/05-기술-블로그-개설/img-00.png)

Docusaurus is an open-source project created by Meta and is an SSG (Static Site Generator) used by various companies. It has well-organized official documentation, a **vibrant** community, and—most importantly—we trusted it because it provides a deep architecture like the one described above.  

Here are the factors I considered when comparing platforms:

| **Platform** | **Pros** | **Cons** | **Selection Status** |
| --- | --- | --- | --- |
| **Velog** | Easy to set up and developer-friendly | Limited customization options for themes and document structuring | On hold |
| **Tistory** | Allows skin customization and is widely used | Lack of Markdown support and difficulty managing via code | On hold |
| **Docusaurus** | Allows you to **fully own the site through code** and **integrate documentation and blogs** for structured organization. **Automation through Notion integration is highly advantageous** | Requires significant effort for initial setup and building the deployment pipeline | **Final Choice** |

I was surprised to find that there is official documentation, an active community, and even an architecture like the one shown below.

![image](/img/blog/05-기술-블로그-개설/img-01.png)

In addition, it includes plugins, routing, SSG (Static Site Generation), and client architecture.  (Reference link: [Docusaurus Advanced](https://docusaurus.io/docs/advanced) )

### Notion to Docusaurus Synchronization

To publish my posts publicly, I set up a synchronization pipeline by following the steps below.

##### 1. Writing a Notion post

- We’ve been using Notion for collaboration for a long time, so I continued to use it for blog posts just as I always had. 

*Screenshot of the Notion workspace where we draft technical blog posts within our team*

 ![image](/img/blog/05-기술-블로그-개설/img-02.png)

##### 2. Configuring Docusaurus 

- For detailed CLI configuration, I recommend referring to the official documentation ([Docusaurus CLI](https://docusaurus.io/ko/docs/cli)). I linked our URL and GitHub page in the `docusaurus.config.ts` file.

```typescript
const config: Config = {
  title: 'SceneMakerAI',
  tagline: 'Repurposing Broadcast Content with Open-Source AI — SceneMakerAI Technology Blog · Documentation',

  ... 
            sameAs: ['https://github.com/SceneMakerAI'],
            parentOrganization: { '@type': 'Organization', name: 'Solbox Inc.' },
          },
          {
            '@type': 'WebSite',
            name: 'SceneMakerAI Docs',
            url: 'https://doc.scenemaker.solbox.com',
          },
        ],
      }),
    },
```

##### 3. Copying from Notion to MD

- To use the Notion API, you need to generate a token and verify the ID for each database.

```bash
NOTION_TOKEN= 
...
NOTION_RELEASE=
NOTION_INSTALL=
```

- We set up a system using the `notion_to_md.py` script so that Notion content appears on the build server in Markdown format.

 ![image](/img/blog/05-기술-블로그-개설/img-03.png)

##### 4. Workflow Synchronization

- We completed the CI setup by separating the build and deployment processes using GitHub Actions.
  - **Build**: Read the code from the main branch and build the converted MD files into static files (HTML/CSS/JS) (`npm ci` followed by `npm run build`)

  - **Deploy**: Automatically deploys the built static files to the production domain ([doc.scenemaker.solbox.com](http://doc.scenemaker.solbox.com/))

  - *Screenshot of the successfully completed GitHub Actions build and deployment workflow*

### final result: the Notion layout perfectly converted into a Docusaurus theme and deployed* Conclusion

---

This process wasn’t entirely smooth—it was a **Docusaurus migration project** that took much longer than expected. 

In particular, the biggest hurdle was ensuring that **bidirectional synchronization between Notion and MD (Notion to MD, MD to Notion)** worked seamlessly without exception. 

I spent quite a bit of time troubleshooting as I encountered numerous rendering errors during the synchronization process—converting Notion’s unique block styles, custom toggles, and image embed paths into Markdown files without breaking them, 

and then perfectly aligning them with Docusaurus’s themes and SEO-optimized layouts.

Still, once we’d built our own automation framework to some extent, things started to pick up speed—simply writing the posts was enough for them to be automatically deployed. It’s a truly fascinating tool that made all the hard work worthwhile.
